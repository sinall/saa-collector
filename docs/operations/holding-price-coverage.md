# 持有期行情与复权覆盖

## 问题与实现

指数成员决定选股范围，但移出指数不代表已经卖出。若采集每个月仅覆盖当月成分股，原成员在持有期末可能没有行情或复权，研究收益标签因此缺失。此次只扩充行情数据覆盖，不扩大财务数据、因子截面或选股范围。

`historical_quote`、`price_adjust_factor` 复用既有任务，新增 `params.index_lookback_months`，默认0，允许0～36整数。非0窗口仅允许这两类任务的 `INDEX` 范围且必须有指数代码；无迁移。

例如目标2025-06-30、窗口3，采集范围为6月末以及3、4、5月末的成分股并集。每个快照取不晚于对应日期的最新指数权重；不读取未来成员。采集仍写入目标月份的行情/复权，回看仅扩展股票范围。该范围对应月末决策、三个月持有的研究；其他持有期应单独配置窗口。

```mermaid
flowchart LR
  A[目标月与回看月末的指数成员] --> B[成员并集]
  B --> C[行情与复权月末采集]
  C --> D[精确月末交易日完整度检查]
  D --> E[持有期收益研究]
```

复权的日期区间请求改为读取交易日历、逐交易日调用数据源，筛选指定股票后保存。不再一次查询跨多年的全市场复权。指数任务已有指定交易日路径保持不变。长区间调用量会增加，历史修复优先使用按目标日期拆分的任务。

开启窗口时，`skip_existing` 检查精确目标交易日且值非空、大于0；月中有一条记录不再代表月末数据完整。日程编辑页保留已有params，避免丢掉指数、缓存、跳过已有数据等配置。

## 当前历史修复请求

[请求文件](../research/holding-price-coverage-v1/collect-plan-request.json)由冻结缺口CSV离线生成，没有连接数据库/API，没有执行采集。

- 130只股票、206个股票×目标日期，2015-06-30～2026-02-27。
- 行情183个目标键；复权206个目标键。
- 合并成2个任务，顺序执行；分别为行情和复权。
- 行情：111只股票，2015-06-30～2026-01-30，128个月。
- 复权：130只股票，2015-06-30～2026-02-27，129个月。
- 范围 `SELECTED`，`FIXED`，`data_frequency=monthly`，`skip_existing=false`。
- 允许重采中间月份，最多覆盖30,978个股票×月份×类型组合（行情14,208、复权16,770）。实际记录数取决于上市时间、停牌和数据源返回，不保证每个组合有记录。
- 源CSV SHA256见 [manifest](../research/holding-price-coverage-v1/manifest.json)。请求中保留六位股票代码，不按目标日期指数成员重新筛选。

生成命令（在saa-collector目录）：

```bash
python3 scripts/build_holding_price_repair.py \
  ../mfactor/docs/research/oracle-guided-reverse-modeling/quarter-start-trading-v1/top30-missing-diagnostics/holding-price-gap-request.csv \
  docs/research/holding-price-coverage-v1
```

JSON可提交到现有采集计划创建接口；创建与执行是两个动作。生产执行前重新只读检查这206个目标键，确认缺口仍存在。根据用户要求，同类缺口合并成完整日期范围，涉及股票的中间月份允许重采；不是全市场重采。任务内部按月末查询，约257个月末请求，不把复权展开为十几年的逐日采集。

## 后续日程建议

保留现有全市场历史行情日程9，不重复建立指数行情日程。补充一条中证800复权月度日程，参数示例见 [日程请求](../research/holding-price-coverage-v1/adjustment-schedule-request.json)。请求默认禁用，部署验收后再启用。每月1日采集此前最近数个交易日对应的月末；窗口3保留原成员。更长IC标签的覆盖不能由3个月窗口保证，须另行扩大。

月度热力图选择指数后，可设置“回看月数”。非0时仅历史行情与复权两行按持有期并集检查精确月末；其他数据类型保持原口径。API查询示例：

```text
GET /api/data-completeness/heatmap/?frequency=monthly&scope=index:000906&index_lookback_months=3
```

窗口进入缓存键，避免与旧指数口径混用。零窗口保持旧完整度口径。

## 执行 review：影响、风险、验证与恢复

本地代码已实现，但本文及JSON不会自动部署、创建生产计划、启用日程或写入业务表。

执行范围：部署collector相关后端/worker与前端；以合并请求创建并执行历史修复计划；新增禁用的复权日程，验证后启用。业务写入是 `saa_prices_ex` 和 `saa_price_adjust_factors` 的合并任务股票与日期范围（含中间月末）；任务/计划/日程表也会新增记录。无schema migration，无mfactor run/教师训练，无冻结研究结果覆盖。

风险：数据源可能没有停牌、退市等目标记录；不能用旧价格或旧复权强填。任务成功只代表请求结束，不代表所有目标键补齐。历史复权或行情变化可能影响后续重新计算，现有冻结研究不随之修改。逐日复权增加外部调用量；2个顺序任务按月末逐步查询，避免并发放大。

执行前：通过父仓库统一只读入口导出合并任务范围内现有整行内容和存在性（不能只备份206个缺口键），记录备份时间、任务请求、版本和原日程配置。核对缺口后先执行一个目标月，确认数据日期、股票范围、价格和复权均合理，再执行剩余月份。

执行后：按清单逐键核验精确日期行情、复权值与有效性，列出仍缺数据及原因；检查日程配置、日志和热力图3月窗口。随后另建研究补充输出，比较冻结评判与补齐数据后的覆盖、Top30指标，不能直接改旧结果。

恢复：停止相关计划、禁用新增日程；回退collector应用版本。业务数据按执行前备份对指定键恢复，新增键仅在核对后删除，已有键恢复整行；禁止整表恢复。恢复数据属于生产写操作，须另外确认。停止采集或回退代码不会自动回滚已写数据。

另一个独立问题：mfactor仍可能用期末指数成员筛收益。此次采集扩展不会改变该过滤，需要后续独立修复和冻结研究对照。
